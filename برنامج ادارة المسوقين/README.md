# نظام إدارة المسوقين - بصمة سوفت

إصدار Windows المكتبي متوفر عبر الملف `Basma-Marketers.exe` في مجلد المشروع.

## تشغيل إصدار Windows
1. شغّل `Basma-Marketers.exe` أو اختصار سطح المكتب «إدارة المسوقين - بصمة سوفت».
2. يفتح النظام في نافذة مستقلة باستخدام Microsoft Edge أو Google Chrome.
3. يتطلب هذا الإصدار وجود Node.js 22.13 أو أحدث، ومتصفح Edge أو Chrome.
4. تبقى قاعدة البيانات في `data\basma-marketers.sqlite` داخل مجلد المشروع، ولا ينشئ المشغّل قاعدة جديدة إذا كانت القاعدة موجودة.

## التشغيل اليدوي
1. افتح PowerShell داخل مجلد المشروع.
2. نفّذ `node start.js`.
3. عند أول تشغيل، سيُنشأ مفتاح تهيئة عشوائي ويظهر في نافذة الطرفية؛ انسخه إلى نموذج إنشاء المدير داخل التطبيق.
4. افتح `http://localhost:4173`.

## إعداد المدير الأول
لا توجد كلمة مرور افتراضية أو تسجيل عام. يقوم `start.js` بإنشاء مفتاح عشوائي مؤقت عند عدم وجود أي حساب، ويعرضه في نافذة الطرفية فقط. انسخ المفتاح إلى نموذج إنشاء المدير، واختر كلمة مرور قوية لا تقل عن 12 حرفاً. لا يتم حفظ مفتاح التهيئة في ملفات المشروع، ويتوقف مسار الإنشاء تلقائياً بعد تسجيل أول مدير.

## ما تم ربطه
- قاعدة SQLite دائمة مع فحوص سلامة وفهارس ومفاتيح أجنبية.
- سجل migrations وإعدادات مدة الحجز ومدة الجلسة.
- حساب مدير أول محمي بمفتاح تهيئة، وتسجيل دخول بجلسات عشوائية مخزنة كـ hash.
- تخزين كلمات المرور باستخدام scrypt وsalt عشوائي.
- حماية CSRF وملفات ارتباط HttpOnly وSameSite وقيود محاولات الدخول.
- فصل صلاحيات المدير والمسوق على الخادم.
- إنشاء حسابات المسوقين بواسطة المدير فقط.
- قاعدة عملاء مركزية، فحص التكرار، الحجوزات المتزامنة، وسجل زيارات غير قابل للتعديل أو الحذف.
- GPS لا يطلب إلا عند ضغط المستخدم زر تسجيل الموقع في نموذج الزيارة.
- الواجهة تقرأ العملاء والزيارات من الخادم ولا تستخدم بيانات Demo المحفوظة محلياً.

## واجهات API الأساسية
- `GET /api/health`
- `GET /api/setup-status`
- `POST /api/bootstrap` (مرة واحدة، مع مفتاح التهيئة)
- `POST /api/login` و`POST /api/logout`
- `GET /api/me`
- `GET/POST /api/users` (للمدير)
- `GET/POST /api/customers`
- `GET/POST /api/reservations`، و`DELETE /api/reservations/:id` (إلغاء المدير)
- `GET/POST /api/visits`
- `POST /api/visits/:id/corrections`
- `GET /api/visit-corrections` و`PATCH /api/visit-corrections/:id` (مراجعة المدير دون تعديل سجل الزيارة الأصلي)

## ما لم يكتمل بعد
- المبيعات واعتمادها والاستردادات وقواعد العمولات والمدفوعات.
- واجهة المدير لمراجعة طلبات التصحيح (واجهات API للمراجعة موجودة)، وإدارة الحسابات (تعطيل/إعادة تعيين).
- المزامنة دون إنترنت، الخرائط، رفع الصور، وتوزيع التطبيق على شبكة/استضافة HTTPS.
- التقارير المركزية المتقدمة.

## تنبيه تشغيل مهم
قاعدة SQLite هذه مركزية على جهاز الخادم المحلي فقط؛ لن تصبح متاحة عبر الإنترنت تلقائياً. للوصول من أجهزة متعددة يلزم استضافة خادم آمنة أو شبكة داخلية مع HTTPS وجدار حماية مضبوط. لا تستخدم بيانات عملاء حقيقية قبل ضبط مفتاح المدير، واختبار النسخ الاحتياطي، وتأمين استضافة الخادم.
